# 精度问题调试思路

## 问题本质

优化后的输出与 baseline 不一致。需要判断：这是正常的浮点累积偏差，还是代码 bug？如果是 bug，在哪里引入的？

## 思路 1：判断发散模式

先分类，再采取不同策略：

| 模式 | 特征 | 说明 | 处置 |
|------|------|------|------|
| 突变型 | 某个位置 diff 从 ~1e-5 突跳到 0.1+ | 几乎一定是实现 bug | 定位突变点对应的代码逻辑 |
| 累积型 | diff 缓慢均匀增长（1e-5 → 1e-4 → 1e-3） | 浮点非结合性导致 | 通常可接受，确认最终 diff 在阈值内 |
| 周期型 | 在某个输入长度/尺寸后突然发散 | 边界条件错误 | 检查位置编码、mask、cache 的边界处理 |

**判断方法**：将每个位置/步骤的 diff 绘制成趋势，观察是平滑增长还是突变。

## 思路 2：二分缩小范围

当确认是 bug（突变型）时，通过“对半切分”快速定位：

```
1. 先确定问题在模型的哪个大块
   → 分别对比每个大块的输出与 baseline
   → 找到第一个出现显著偏差的块

2. 在问题块内继续缩小
   → 逐层对比中间输出，找到 diff 突变的层
   → 在该层内对比各子模块的输出

3. 定位到具体操作
   → 对比该子模块的输入和输出，确认是输入就已有偏差还是该操作引入的
```

**核心原则**：每次切分后，问题范围减半。不要试图一步到位，而是逐步缩小。

## 思路 3：检查常见根因

定位到问题位置后，按以下分类检查：

### 参数传递错误

优化改写过程中遗漏了某个参数：
- mask 未传递（padding 位置参与了不该参与的计算）
- 位置编码的方向参数错误（encoder 双向 vs decoder 单向）
- 缩放系数的值不正确

**思路**：逐行对比优化后的代码与原始实现，检查每个参数是否完整传递。

**典型案例**：扁平化 forward 中遗漏了 encoder_attention_mask → cross-attention 未 mask 掉 padding 位置 → diff 在特定 step 后突然增大。

### 内存别名 / 引用共享

多个计算共享同一块内存，后续写入覆盖了先前的数据：
- 预分配 buffer 被多层复用→ 后面层的写入覆盖了前面层的 cache
- 权重共享（如 encoder/decoder 共享 embedding）→ 对一端 dtype 转换影响另一端

**思路**：检查传入 cache 或共享结构的 tensor 是否是独立副本（是否需要 `.clone()`）。

**典型案例**：
- 预分配的 QKV buffer 被多层共用，DynamicCache.update() 仅保存 tensor 引用 → 后续层覆盖前面层的 cache → 第 2 步起生成退化为重复字符
- model.decoder.half() 导致 shared embedding 也变 fp16 → encoder 侧精度意外降级

### 边界条件

位置编码、mask、cache 在特定长度/步数时的行为：
- 增量 decode 时的位置编码计算方式与全量计算不一致
- causal mask 的尺寸与实际序列长度不匹配
- cache 容量用尽后的行为

**思路**：用多个不同长度/尺寸的输入测试，观察哪个长度开始发散。

**典型案例**：增量 decode 时 position bias 用 `compute_bias(1, key_len)` 而非 `compute_bias(key_len, key_len)[-1:]` → 位置信息丢失 → diff 在某个 step 后指数级增长。

### dtype 不一致

优化过程中引入了非预期的 dtype 转换：
- 融合算子内部做了隐式 dtype 转换
- 去掉了原始代码中的 overflow 保护（如 fp16 clamp）
- 深层模型在低精度下累积超出表示范围（NaN/Inf）

**思路**：检查每个子模块输出的 dtype 是否符合预期；检查是否有 NaN/Inf。

**典型案例**：去除了框架中的 fp16 clamp 保护后，深层模型在 fp16 下累积超出表示范围 → 输出出现 NaN。解决：恢复 clamp 或改用 BF16。

## 思路 4：区分“正常偏差”与“bug”

不同的 matmul 实现（原生 torch vs NPU 算子）的运算顺序不同，每次调用会产生微小数值差异。经过多层多步累积，diff 会增长，这是**浮点非结合性，不是 bug**。

**判断方法**：
- diff 平滑缓慢增长 → 浮点累积，可接受
- diff 在某步突跳一个数量级以上 → 代码 bug，需定位

## 调试流程总结

```
精度不通过
  |
  ├─ 确认对比对象正确（原始未优化的 baseline）
  ├─ 确认确定性条件已设置（随机性关闭、JIT 禁用）
  ├─ 判断发散模式（突变 / 累积 / 周期）
  ├─ 突变型 → 二分定位 → 检查常见根因
  ├─ 累积型 → 确认最终 diff 可接受
  └─ 周期型 → 检查边界条件
```
