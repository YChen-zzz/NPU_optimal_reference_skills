# 基线管理策略

## 问题

精度对比的前提是有一个可信的 baseline。如果 baseline 来源不对，整个对齐结论无效。

## 基线来源优先级

按以下顺序确认，不可跳过：

1. **官方基线**：模型官方 README、示例输出、benchmark 或文档中给出的标准结果
2. **用户 GPU 基线**：用户在 GPU 上实际跑出的结果
3. **CPU 调试用途**（仅辅助）：用于定位 PyTorch/NPU 路径问题，不作为最终对齐结论

## 强制规则

- **先查官方基线，再写对比脚本**：不要进入精度对比流程后才发现基线来源不对
- **官方基线不足时必须询问用户**：是否已有 GPU 结果、结果在哪个目录、含哪些文件
- **禁止默认 CPU 作为最终基线**：CPU 路径容易跑通不代表它是官方基线
- **阈值必须在比较前声明**：不能先看到 mismatch，再临时放宽阈值后写成“全部对齐”
- **样例级对齐 ≠ 模型级对齐**：官方示例只能证明示例覆盖范围内的结果一致

## CPU 对比的合法用途

仅以下情况可以做 CPU 对比：
- 用户明确要求
- 官方文档明确把 CPU 结果作为标准
- 仅作为本地调试辅助（报告中必须标注“仅用于调试，不作为最终对齐结论”）

## 待确认时的询问模板

官方基线缺失时，至少问清：
- 是否已有 GPU 侧运行结果？
- 结果文件在哪个目录？含哪些内容（日志、推理输出、指标文件）？
- 希望 agent 直接读取目录分析，还是只给对比方法由用户自行执行？

## 报告措辞

- 只做了 CPU 对比：“当前仅完成 CPU vs NPU 调试性比较，不作为最终精度对齐结论”
- 只对齐了官方示例：“官方示例级推理结果基本对齐，尚未覆盖完整评测集”
